# Bangumi Analyzer v2.0.0 — Windows x64 便携版

这是完整、可写的本地正式 Analyzer，不是只读 Public Demo。
无需安装 Node、pnpm、Git、Python、Visual C++ 编译工具或修改源码。
程序自带 Node 24 运行时。无需管理员权限，不添加开机启动，不改变系统环境。

## 第一次使用（只需鼠标）

1. 把收到的 ZIP 保存到电脑，例如「下载」文件夹。原始 ZIP 和随附的 .zip.sha256 校验文件留在程序目录之外。
2. 为程序准备一个**独立、全新、空白的专用文件夹**，例如 D:\Analyzer 或「桌面\Bangumi Analyzer」。
   右键 ZIP →「全部解压缩」，在目标位置中明确选择这个专用文件夹，再完成解压。
   **不要把 ZIP 内容直接散解到桌面、下载文件夹或其他已有文件的目录，也不要把原始 ZIP 放进程序文件夹。**
   中文、空格路径可以使用；不要放 Program Files、只读目录、网盘同步目录、网络盘或符号链接目录。
   不同解压软件可能自动增加一层文件夹：解压完成后，找到同时包含 Start-Analyzer.bat、runtime、packages、
   node_modules 和 checksums.json 的那一层，它才是程序目录。该目录只保留原包解出的文件与运行后自动生成的数据，
   不放 ZIP、校验文件、截图、下载文件或其他杂物。
3. 在上述程序目录里双击「Start-Analyzer.bat」。不要在 ZIP 内启动，也不要双击 runtime 文件夹里的 node.exe。
4. 等窗口出现「Analyzer ready」，默认浏览器会打开本机页面。保留这个窗口。
   若未自动打开，把窗口中的 http://127.0.0.1:数字/ 地址复制到浏览器地址栏。
5. 新用户没有任何收藏、账号、Token、AI Key 或旧设置；空白收藏页是正常状态。
   按首次引导设置昵称（可跳过），在「设置 → Bangumi」填写自己的用户名或数字 UID。
   用户名不是邮箱或登录密码；是个人主页最后一段。
6. Access Token 可选。只同步公开收藏可先不填；私有收藏需要你自己的个人令牌。
   可在 Bangumi 官方账号的个人令牌页面生成。只填到本机 Analyzer，不发给别人。
   保存后按页面指引验证，点击同步。配置成功不等于同步成功，以同步结果为准。
7. 首次同步可能较慢，需要联网；失败时看提示后重试，不要删除数据库。
   深度同步会额外请求作品关系和人员信息，更慢。未配置 AI 不影响收藏同步、统计、画像证据及治理。

## 每天打开、关闭

- 打开：双击 Start-Analyzer.bat。不要重复启动同一文件夹；已有窗口会提示占用，不会结束任何进程。
- 关闭：回到那个黑色运行窗口，按一次回车，等「Stopped」出现，再关窗口。
  这会等待同步、后台任务和数据库安全退出。关闭浏览器页面不会停止程序。
- 不要强制关机、任务管理器结束进程或拔掉数据盘。意外退出后重新启动，程序会执行既有恢复检查。
- 默认只允许本机访问。如果默认端口已被其他程序占用，会另选空闲端口，显示新的地址；不会连接或停止那个程序。
  网页端浅色 / 深色 / 跟随系统主题设置已持久化保存在本机 `data/config.json` 中，切换不同端口重启后仍会自动保留；若通过 Companion 运行，还会与 Companion「Analyzer 网页端主题」保持同步。

## 退出 / 断开 Bangumi 账号（分发修订 r2）

1. 打开「设置 → Bangumi」，点击「断开 Bangumi 账号」，阅读说明后点「确认断开」。
2. 程序会取消并等待当前同步结束，再清除本机保存的 Bangumi 用户名和 Access Token；
   如果请求仍在收尾，请等待，不要强制关闭窗口。失败时会明确报错，不会假装已退出。
3. 设置和身份区显示「未绑定 Bangumi 账号」。本地收藏、评分、人工治理、历史分析、快照、备份、
   昵称/头像及独立 AI API 配置均保留，已有本地数据仍可离线使用；新同步需要先重新绑定。
4. 要恢复同步，在原位置重新填写原账号用户名（或数字 UID）及可选 Token，保存后同步。
   重新绑定需要联网核对原账号 UID。原账号改过用户名时，仍以 UID 为准。
5. 同一个数据库保留原账号归属，即使当前收藏为空也不能换成其他账号。
   要使用另一个账号，请把原始干净 ZIP 解压到另一个全新目录；不要复制旧目录的 data。

「清除 Token」只是清令牌、保留用户名；「断开 Bangumi 账号」才会清除两者并停止当前同步。
断开只作用于本机 Analyzer，不退出浏览器里的 Bangumi 网站，也不撤销 Bangumi 服务器上的令牌。
不要因为断开就把曾使用过的整个目录发给别人——本地个人数据仍然保留。
旧库若缺少可证明的账号归属，断开后也不会凭新填的账号强行认领；请先保留数据并寻求归属核查。

## 我的数据在哪里？如何迁移和备份？

首次运行自动生成本文件夹下的 data：

  data/config.json       个人设置、Bangumi Token 和可选 AI Key（敏感）
  data/bangumi.db         个人 SQLite 数据库
  data/bangumi.db-wal     运行期间可能存在的数据库事务文件
  data/bangumi.db-shm     运行期间可能存在的共享内存文件
  data/covers            离线封面
  data/wallpapers        自选壁纸
  data/backups           程序生成的数据库备份
  data/logs              本地日志

- 「设置 → 数据管理」可备份、下载、导出、导入及自检。导出收藏含个人内容，不要随意公开。
- 要搬到另一台电脑或长期备份：先按回车停止，再复制整个程序文件夹，特别是整个 data。
  不要在运行时只复制 bangumi.db；WAL 中可能仍有未合并的数据。
- data/config.json 是明文敏感配置，依赖 Windows 账号/文件权限保护，不是加密保险箱。
- 同步只读取 Bangumi，不反向改你的 Bangumi 收藏。
- 分发给朋友时：只转发最初收到的干净 ZIP。绝对不要把自己运行后的文件夹重新压缩发送。
- 升级：本包不提供自动升级或降级。不要覆盖正在运行的旧版本，不要混拷 JS 文件。
  拿到后续正式升级说明后，先停机备份，再按说明处理；本包没有验证旧版本迁移。

## 正式功能和可选联网能力

保留收藏同步、搜索/筛选、作品详情、统计/趋势、画像证据与快照、Series/Franchise 治理、
主动隐藏、数据中枢检测与 Preview → Execute → Verify、导入/导出/备份、背景/材质、离线缓存等正式功能。
首次引导可跳过，也可在「设置 → 关于」重新打开。

已同步数据的核心分析与治理可离线用；新同步、未缓存图片、远端内容补全需要联网。
AI 翻译/总结是可选增强，需要自行在「设置 → AI」配置兼容服务、模型和自己的 Key；
它可能发送作品简介或画像证据到你选择的服务并产生费用。默认关闭、无内置 Key，
本分发验证没有调用真实付费 AI。网络不可达、限流、账号权限与服务商费用不是便携包能消除的限制。
如需代理，在 Analyzer 设置里填写自己的代理；便携启动器不继承开发终端里的代理、账号或 AI 环境变量。

## 常见问题

### 启动报 Unexpected package file

这表示程序目录中出现了交付清单以外的文件，**不等于缺少 Node 或 pnpm，也不表示收藏数据库已损坏**。
例如把 ZIP 内容直接解压到桌面，而原 ZIP 也在桌面，完整性检查就可能把原 ZIP 或其他桌面文件视为多余文件。

1. 查看报错中 `Unexpected package file:` 后面的文件名，确认 Start-Analyzer.bat 实际所在的程序目录。
2. 如果点名的是你自行放入的原 ZIP、.zip.sha256、截图等，把它移到程序目录之外再试；不要盲目删除不认识的文件。
3. 若文件混杂、无法确认，优先重新建立一个全新空白专用文件夹，把原 ZIP 完整解压到那里，按上面的步骤启动。
   如果旧目录已经产生个人 data，先停止旧程序并备份整个 data；保留原目录，后续按本 README 的迁移说明处理，
   **不要删除 data，也不要覆盖它来“修复”校验错误**。
4. 不要删除程序必需文件、修改 checksums.json 或绕过完整性检查。运行自动生成的 data 和会话锁由程序管理，无需手工清理。

### 其他问题

- Windows 提示未知来源/安全软件拦截：本包未做商业代码签名。
  先核实发送者和随包 SHA-256，遵循电脑管理规定；不要关闭杀毒软件，不要给不可信程序管理员权限。
- 缺文件 / Missing or damaged file：重新完整解压原 ZIP 到新目录。不要把新包覆盖到已有 data 的目录，先备份。
- 窗口闪退：从文件管理器右键在终端打开后运行 Start-Analyzer.bat，或保留报错截图。
- This copy may already be running：使用已有运行窗口；程序不会按 PID 强制结束进程。
  崩溃后确认该副本的程序均已停止；重新启动会清理已死亡会话。
  如 PID 被其他程序复用而仍被拒绝，重启 Windows 后再试，不要随便结束那个进程。
- 无法写入 / Access denied：把整个文件夹移到你有权限的本地目录，避免只读、网络和网盘目录。
- 无法同步：检查用户名、自己的 Token、网络与代理，看界面错误；不要填登录密码，不要向维护者发 Token。
- 空白页：确认服务窗口仍运行，并使用本次显示的地址；必要时刷新浏览器。
- 不要把服务暴露公网、做端口映射或反向代理。它是单机单用户工具，没有公共访问的账号认证。

## 包内容与真实性

runtime 是随包运行时；packages 是正式程序构建；node_modules 是运行依赖，不要删改。
release.json 记录源码哈希、Node 版本与生产依赖；checksums.json 用于启动时完整性检查。
外部 .zip.sha256 可用于核对传输完整性（不能代替可信发送者或代码签名）。
runtime/LICENSE、依赖目录中的许可证和 THIRD_PARTY_NOTICES.txt 保留第三方授权说明。
这是第三阶段便携交付，不含图形化安装器、二次元安装桥梁、自动更新器或云账号。

支持范围：工程验证环境为 Windows x64；用户已反馈 r2 在另一台 Windows 电脑完整解压后可直接启动，无需另装 Node 或 pnpm。
这项实测仅确认该电脑的解压启动，不代表全部功能或所有 Windows 环境均已验收。Windows ARM64、旧 Windows、非 Windows及
其他企业管控/防病毒组合仍未获全面验证；请先少量试用并备份数据。
